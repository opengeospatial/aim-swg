== AIM overview

=== Design principles

AIM is a domain model for agriculture published as a set of modular OWL ontologies. It follows these principles:

* *Reuse before minting.* Concepts are taken from established vocabularies (SOSA/SSN, GeoSPARQL, OWL-Time, RDF Data Cube, SAREF/SAREF4AGRI, FOODIE, INSPIRE, FIWARE Smart Data Models) and aligned, rather than redefined. Only a small number of terms are minted in AIM namespaces.
* *Modularity.* Each agricultural sub-domain is a separate module that can be adopted independently. Users import only the modules they need.
* *Layering.* Generic concepts are kept separate from agriculture-specific ones, so the generic layer can be shared with other domains.
* *Persistent identification.* Each module has a persistent ontology IRI and a version IRI under `https://w3id.org/demeter/`.

=== Architecture

AIM version 3.0 is organized in four tiers, as shown in <<table_tiers>> and <<fig_aim_architecture>>.

[[table_tiers]]
.AIM tiers
[cols="1,2,5",options="header"]
|===
|Tier |Module(s) |Role
|1 |Cross-Domain |Generic concepts applicable to any domain: features and geometry (GeoSPARQL, Simple Features), observations and sensing (SOSA/SSN), time (OWL-Time), quantities and units (QUDT, QU), statistical data (RDF Data Cube), agents (FOAF) and provenance (PROV-O). Imports no other AIM module.
|2 |AgriCommon |Concepts shared by all agricultural modules, such as farmer, farm holding, agricultural certificate, image and taxonomic rank, and common descriptive properties (identifiers, names, dates, addresses). Imports Cross-Domain.
|3 |AgriFeature, AgriCrop, AgriIntervention, AgriAlert, AgriProduct, AgriProperty, AgriSystem, AgriPest, FarmAnimal |Agricultural sub-domains. Each imports AgriCommon.
|4 |AIM Agri Profile |Aggregates all Tier 3 modules and the AIM to NGSI-LD alignment. Defines no terms of its own.
|===

=== Versioning

Each module declares `owl:versionInfo "3.0"` and a version IRI formed by appending `/3.0` to the ontology IRI. Modules import each other by version IRI, so that a given version of a module always resolves to a consistent set of dependencies.

NOTE: In version 3.0, AgriCommon imports Cross-Domain by its ontology IRI (`https://w3id.org/demeter/crossDomain`) rather than by its version IRI. The AIM Agri Profile likewise imports the NGSI-LD alignment without a version IRI.
